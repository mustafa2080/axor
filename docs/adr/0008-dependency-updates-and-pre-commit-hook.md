# ADR-0008: تحديث الاعتماديات آلياً وفحص ما قبل الـ commit

- **الحالة:** منفّذ (2026-10-27) — بند من قسم 20 في `TASKS.md`. مفيش تغيير في سلوك النظام، أدوات تطوير فقط.
- **السياق:** المستودع عليه CI (typecheck وlint وtest وbuild وaudit)، لكن مفيش حاجة بتنبّه لتحديثات الاعتماديات، ومفيش فحص محلي بيمنع commit فيه lint أو typecheck مكسور قبل ما يوصل CI.

## القرار

1. **Dependabot بدل Renovate:** مدمج في GitHub ومفيش حاجة نركّبها. الإعداد في `.github/dependabot.yml`.
2. **اعتماديات npm:** فحص أسبوعي (الاثنين 06:00 بتوقيت القاهرة) للجذر و`frontend` و`backend`. تحديثات `minor` و`patch` بتتجمّع في PR واحد، وتحديثات `major` بتيجي PR لوحدها عشان تتراجع بعناية. حد أقصى 5 PRs مفتوحة. رسائل الـ commit بتبدأ بـ `chore(deps)`.
3. **GitHub Actions:** نفس الجدول، كل التحديثات في PR واحد، والبادئة `chore(ci)`.
4. **مفيش دمج تلقائي:** كل PR بيشغّل الـ CI الموجود (`on: pull_request`) ولازم يعدّي قبل ما حد يدمجه.
5. **pre-commit hook:** ملف `.githooks/pre-commit` بيشغّل `pnpm lint` ثم `pnpm typecheck` (أدوات سريعة: oxlint وtsc). الاختبارات والـ build مش في الـ hook عشان ما يبقاش بطيء؛ بتتفحص بـ `pnpm check` وفي الـ CI.
6. **التركيب أوتوماتيك:** سكربت `prepare` في الـ `package.json` بيضبط `core.hooksPath=.githooks` عند `pnpm install`، فأي حد بيستنسخ المستودع بياخد الـ hook من غير خطوة يدوية. من غير أداة إضافية (husky وlint-staged مش مطلوبين).
7. **`.gitattributes`:** `.githooks/*` بينتهي بـ `LF` دايماً، لأن `CRLF` على ويندوز بيكسر سكربتات `sh`.
8. **التجاوز مسموح لكن مش بيهرّب من الـ CI:** `git commit --no-verify` بيتخطى الـ hook محلياً، والـ CI لسه بيفحص كل push.

## خارج النطاق

- قرار أدوات الفحص نفسها (إبقاء `oxlint` أو الانتقال إلى ESLint + Prettier): لسه مستني المدير. الـ hook بيستخدم أي أمر `lint` معرّف في الحزم، فهيشتغل مع أي من الخيارين.
- `lint-staged`: الفحص حالياً على المشروع كله (حوالي ثانية للـ lint)، فالفرق في الوقت صغير. لو بقى بطيء نرجع له.

## النتائج

- أي commit فيه خطأ lint أو typecheck بيتوقف محلياً قبل ما يستهلك دقيقة CI.
- الاعتماديات بتتراجع أسبوعياً في PRs صغيرة، وأي تحديث بيتفحص بنفس الـ CI.
- محدودية معروفة: إعداد Dependabot مش ممكن يتجرّب محلياً. هيتأكد فعلياً أول ما GitHub يقرأه بعد الـ push (صفحة Insights → Dependency graph → Dependabot).
