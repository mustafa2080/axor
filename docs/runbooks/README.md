# Runbooks — AXOR

إجراءات تشغيل مكتوبة بخطوات قابلة للتنفيذ. كل أمر مكتوب هنا إما اتجرّب فعلاً (ومعلَّم بتاريخ التجربة)، أو معلَّم «لم يُجرَّب» أو «ينتظر قرار».

| الملف | الغرض |
|---|---|
| [deploy.md](./deploy.md) | نشر إصدار جديد، والتحقق منه، والتراجع عنه |
| [backup-restore.md](./backup-restore.md) | النسخ الاحتياطي والاستعادة، وأهداف RPO/RTO المقترحة، وسجل تجارب الاستعادة |
| [incident-response.md](./incident-response.md) | تعطل الخدمة أو قاعدة البيانات أو البريد |

## ما لسه ما اتحدّدش (يحجب أجزاء من الـ runbooks)

- **منصة الاستضافة:** `infra/deployment/` فاضي. خطوات النشر هنا محايدة للمنصة، ومحتاجة تتكمّل بعد اختيارها.
- **مخزن الأسرار والـ backups خارج الجهاز:** مفيش قرار لسه.
- **مزوّد البريد:** مفيش بريد في النظام حالياً (استعادة كلمة المرور والتحقق من البريد لسه ما اتبنوش)، فقسم البريد في `incident-response.md` تمهيدي.
- **المراقبة والتنبيهات:** `infra/monitoring/` فاضي، فمفيش تنبيه تلقائي. الكشف عن الأعطال حالياً يدوي.
- **بيئة staging:** مفيش.

> أي تعديل في سلوك النظام يأثّر على خطوة هنا (متغير بيئة جديد، أمر جديد، instance تاني) لازم يتحدّث الـ runbook المعني في نفس الـ PR.
